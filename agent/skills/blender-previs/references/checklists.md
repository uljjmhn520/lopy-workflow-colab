# 检查清单

每一关都要能回答「凭什么说通过」。**技术通过 ≠ 使用者认可**，两者分开记录。

## 1. 需求确认后

- [ ] 人物识别特征、场景、走向、风格、禁则都写进需求确认表
- [ ] 需要后制的文字（菜单、简讯、告示）已标记，**不交给模型生成**
- [ ] 台词与停顿位置已定，能换算成秒数
- [ ] 未经确认的推测都标成「假设」

## 2. 镜位契约

- [ ] 每镜都有 `camera`、`frames`、`lens_mm`、`location`、`target`、`motion`、`visible`
- [ ] 帧数符合 **17n+5**
- [ ] 已列出 `identical_camera_setups` 与 `distinct_setups` 数量
- [ ] 运镜状态（static / push）与提示词一致
- [ ] 已确认哪些镜**只有一人**、哪些**两人必须同框**

## 3. 布置图（生成前）

- [ ] 每镜都算了一张，人工确认座位、朝向、背景、景别、道具
- [ ] 空景镜角色已隐藏、道具保留
- [ ] 没有不该出现的物件（多余窗、杂物、重复人物）
- [ ] 同机位的镜头确认是刻意的，不是误用

**布置图通过 ≠ 对嘴或表演通过。**

## 4. 运镜

- [ ] 运镜是 `.blend` 内的 keyframe，不是算图脚本逐格位移
- [ ] 只有真的要运镜的镜头才有 keyframe
- [ ] 重算验证与原脚本等价（逐格比对）

## 5. 生成前环境

- [ ] Comfy 服务在线、queue 没有别人的工作、显存没被 TTS／LLM 占用
- [ ] 确认实际 ComfyUI 版本与模型（**目录名称不代表实际版本**）
- [ ] 收件锁正确的 Save 节点 ID
- [ ] 每次修正**另存新版本**，不覆写已提交的

## 6. 选镜与返工

逐镜播放完整动态，检查：

- [ ] 提前开口／台词前先动嘴
- [ ] 静默时仍张嘴
- [ ] 角色增生、重复人物
- [ ] 左右换位、座位漂移
- [ ] 帽／眼等道具异常
- [ ] 手部、道具、背景漂移
- [ ] 全脸与肩颈是否有整体表演（不是只有嘴动）

发现问题**先标原因**，只修必要镜头。**禁用嘴／眼 XY 平移贴片修法。**

## 7. 对嘴界线

- [ ] 配音与画面使用同一份音讯
- [ ] 长静默段有闭口引导，且未把身体锁死
- [ ] 未做逐音素量测就照实注明，不写成「完美对嘴」

## 8. 后制

- [ ] 保比例放大（不拉伸画面比例）
- [ ] 字幕**不在低解析度先烧再放大**
- [ ] 原音轨封包保持一致
- [ ] 全片解码、帧数、fps、近黑帧、削波、字幕时序检查

## 9. 交付与归档

- [ ] 成片、字幕、播放入口、采用清单、验证 JSON、README 齐备
- [ ] 保存使用者回馈原文，不擅自升级为「验收通过」
- [ ] 记录耗时**分类**（准备／排队／生成／QA／返工），不要只记总时间
- [ ] 已写回专案纪录（`资源索引/AI短片/`＋入口档）

## 最常见的失误（回看用）

| 失误 | 对策 |
|:---|:---|
| 先批次生成才发现共通缺陷 | 需求访谈＋最难镜先测 |
| 参考影片用途没定义 | 在 `subject_definitions` 写清楚每个 `<Picture N>`／`<Video N>`／`<Audio N>` |
| 标 locked 却写运镜 | 契约与提示词同步 |
| 误以为镜数等于机位数 | 做机位去重 |
| 收错输出（把输入素材当成品） | 锁 Save 节点 ID |
| 把技术检查当美感验收 | 分开记录 |
| 旧待办盖过新结果 | 以最新使用者决策＋采用清单为准 |
