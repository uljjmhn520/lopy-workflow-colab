# 镜位契约（shot contract）

目的：让「分镜」「Blender 相机」「实际生成的画面」三者对得上，并且**可被程式与下一个对话读懂**。

## 为什么需要

本专案已记录的踩坑：
- 分镜改成双人镜，但 Blender 相机仍是单人构图 → 生成结果与分镜不符。
- 标了 locked，提示词却写慢推 → 自相矛盾。
- 13 个镜号看起来很多，实际上**只有 8 种不同机位**（A1＝C3＝E2＝F1、A2＝C2、A3＝D2）。

## 契约栏位

每镜至少要有：

| 栏位 | 说明 |
|:---|:---|
| `shot` | 镜号（A1、B2…） |
| `camera` | Blender 相机物件名（例 `V5_A1`） |
| `frames` | 该镜帧数（**必须符合影片模型对齐规则**，见下） |
| `lens_mm` | 焦段 |
| `location` / `target` | 相机位置与注视点 |
| `motion` | `static` 或 `push`（附距离与帧数、插值） |
| `delivered` | 交付实际采用的是静止还是推进（**必须与 motion 一致**） |
| `visible` | 画面中应该出现谁、谁必须在画面外 |
| `note` | 特殊限制（不举纸、无窗背景、闭口引导…） |

机位重复时另存一个 `identical_camera_setups` 区块，明确列出，并写 `distinct_setups` 数量。

## 帧数对齐（H3）

H3 的帧数必须符合 **17n+5**：

```
length = max(5, round(sec * fps)) + ((5 - (raw % 17)) % 17)
```

先用配音长度决定秒数，再换算成合法帧数；**不要直接抄别的专案的镜长**。

## 运镜的两种状态（不可混用）

| 状态 | 条件 | 提示词必须写 |
|:---|:---|:---|
| **locked（静止）** | 相机在 Blender 内没有任何 keyframe | 明确写「完全锁定三脚架、同焦段同构图、不得推移摇」 |
| **push / 运镜** | 相机运动**必须做成 keyframe 存在 `.blend` 内** | 说明相机运动；参考影片提供运镜 |

**已发生的教训**：v5 全片只有 F1 真的用了推进，A1／D1 交付版是静止；若没有契约表，很容易误以为 13 镜都有运镜。

- `camera_plan_v<N>.json`（机器可读，给脚本与下一个对话）
- 人类可读的镜表（可放在该片 README 或制作计划）

**契约未定案前，不要开始生成影片。**
