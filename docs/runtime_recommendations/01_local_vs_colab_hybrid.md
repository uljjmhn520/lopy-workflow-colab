# 专题一：本地 Tesla T4 与云端 Colab 混合算力分工建议

在开源短视频工作流中，关于“代码和模型到底跑在本地还是云端”，存在一个非常普遍的认知陷阱。本文档深入对比原作者的硬体方案与本地 Tesla T4 实测数据，给出最合理的混合部署方案。

---

## 一、 为什么不能盲目照搬原作者的“仅 H3 上云”策略？

原项目作者在 `cloud/README.md` 中建议：
> *“做法：本机准备、云端只跑 H3。剧本、首帧、配音、剪接在你的电脑做；H3 影片整批送到 Google Colab 跑。”*

### 核心差异：机器配置不对等

| 硬件配置维度 | 原作者本地主力工作站 | 本项目本地环境 (Tesla T4) | 性能差距倍数 |
| :--- | :--- | :--- | :--- |
| **GPU 型号** | **NVIDIA RTX 5090** (GB202 旗舰) | **NVIDIA Tesla T4** (2018 年 Turing) | 跨越 3 代架构 |
| **物理显存** | **32 GB GDDR7** | **16 GB GDDR6** | 显存容量 2 倍差距 |
| **内存 (RAM)** | **96 GB** | **32 GB** | 内存容量 3 倍差距 |
| **FP8 张量计算核心** | **原生 GB202 FP8 Tensor Core** | **无原生 FP8**（仅能软件反量化模拟）| 计算密度差距约 40~50 倍 |

#### 带来的实测耗时断崖：
1. **原作者在本地跑 Stage 2（生图）**：5090 只需 **10 ~ 20 秒** 即可生成一张 2K 高清首帧，根本不需要为生图专门开云端机器。
2. **我们在本地 T4 跑 Stage 2（生图）**：实测单张角色图需 **35 分钟**，附参考图首帧需 **122 分钟（2 小时）**！
3. **结论**：如果照搬原作者的“本机做首帧”，您的全套流水线会被死死卡在第二阶段，每天只能生成 3~4 个分镜首帧，丧失商业制作可行性。

---

## 二、 推荐的混合算力“黄金分割”架构

结合成本、网络传输带宽与显卡架构特性，我们为 **本地 Tesla T4 + Google Colab** 制定如下架构分工：

```text
【本地 Tesla T4 (零成本、即时响应)】             【Google Colab (按需租用、FP8加速)】
┌─────────────────────────────────┐              ┌───────────────────────────────┐
│ Stage 0: 编剧设计与分镜 Prompt   │ ──(纯文本)──>│ Stage 2: 角色立绘与场景首帧   │
│ (Antigravity-CLI 交互完成)       │              │ (Qwen-Image / H3-Image)       │
├─────────────────────────────────┤              │ 实测只需 10 ~ 30 秒 (提速100倍)│
│ Stage 1: BreezyVoice 语音合成   │              ├───────────────────────────────┤
│ 实测只需 14 秒，显存仅 2.1 GB   │ ──(几MB音频)─>│ Stage 3: MiniMax H3 视频渲染  │
│ 零云端成本，零 API 费用         │              │ 实测只需 42 秒 ~ 2.5 分钟     │
└─────────────────────────────────┘              └───────────────┬───────────────┘
                 ▲                                               │
                 │                                               ▼ (回传 2MB 视频)
┌────────────────┴───────────────────────────────────────────────┐
│ Stage 4: FFmpeg 剪辑、EDL 对齐、字幕压制与混音                 │
│ (本地 CPU 毫秒级处理，耗时 5 秒，零成本交付最终成片)           │
└───────────────────────────────────────────────────────────────┘
```

## 三、 各阶段部署决策依据

### 1. 为什么 Stage 1（配音与 ASR 挑音）必须坚守本地？
* **实测指标极佳**：BreezyVoice-300M 批次生成 + Faster-Whisper large-v3 自动听写挑音，在本地 T4 上仅占 **2.14 GB 显存**，耗时仅 **14.0 秒**。
* **零传输成本**：台词音频本地落盘，无需频繁向云端上传未剪辑的候选音频片段。

### 2. 为什么 Stage 2 与 Stage 3 必须迁移至 Colab？
* **硬件特性决定**：现代生图与视频模型（Qwen-Image 2511、MiniMax-H3-Image、MiniMax H3）核心算子均基于 FP8 精度开发。Colab 的现代显卡（G4 / L4 / A100）具备硬件级 FP8 Tensor Core，单镜视频从本地的 87 分钟压缩至 **42 秒 ~ 2 分钟**，生产力暴涨 **50 ~ 100 倍**。

### 3. 为什么 Stage 4（后期剪辑）必须放回本地？
* **算力开销极小**：视频拼接、音量平缩（-16 LUFS）、字幕压制由 FFmpeg 完成，属于纯 I/O 与轻量编码任务，本地仅需 5 秒，完全不值得花费昂贵的云端 GPU 点数。
