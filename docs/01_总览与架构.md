# 01 总览与架构

## 目标

- 每月 5–10 支、每支 1–3 分钟的原创短片，主角是戴美洲狮头套的老师「山狮霸」和三个学生（阿福、阿禾、班长小雯）。
- 16:9 横式、24fps、YouTube 为主。之后要做 Shorts 不裁切成品，而是用 9:16 重新生成。
- 核心是**可重复的制作管线**：换剧本、换角色，同一套流程照样跑。

## 三层架构

```
┌─ 知识层：让人和 AI agent 都知道「怎么做、为什么」─────────────┐
│ CLAUDE.md / AGENTS.md：agent 入口（最新决策写在最上面）          │
│ 专案现况、资源索引：研究、实测、「答案索引」（已验证的做法）     │
│ 记忆：一事一档的使用者偏好、退件理由、专案事实                   │
│ 技能：编剧（shanshiba-drama）、Blender 预演（blender-previs）    │
│ 角色资产卡：定妆照、转面图、表情表、锁定提示词、声音             │
└─────────────────────────────────────────────────────────────────┘
┌─ 全域工具层 C:\AI\tools：所有片、所有 agent 共用 ─────────────┐
│ h3_shot.py、img25.py、breezyvoice_*.py、breeze_batch.py、stt.py、   │
│ pron_check.py、pron_compare.py、gen_music3.py、upscale_vsr.py、 │
│ noise_scan.py、start_comfy                                      │
└─────────────────────────────────────────────────────────────────┘
┌─ 每片脚本层：每支片一个资料夹，复制范本后只改表格 ─────────────┐
│ gen_frames → voice_stage1 → voice_pick → plan_h3 → pipeline_gen │
│ → post_fx → music_scenes → assemble → render_ending → review    │
│ run_queue.sh 串起来，等 GPU 空出来就自动跑（可以过夜）          │
└─────────────────────────────────────────────────────────────────┘
```

### 为什么这样分

- **工具层稳定、每片层可抛**：工具改一次全部受益；每片脚本是「表格＋少量专属特效」，复制上一支改表格最快，不追求抽象化。
- **知识层是重点**：AI agent 每次对话都是新的。把「使用者退件过什么、为什么」写成档案，下一个 agent 才不会重犯。这个专案超过一半的品质提升来自这一层，不是换模型。

## 工具选择

| 环节 | 用什么 | 为什么不用别的 |
|---|---|---|
| 首帧 | OpenAI Image 2.5（云端，medium 画质） | 本机 Qwen-Image 2.1 2K／50 步画质没差，但光线氛围偏白日光、双人镜角色不太像 |
| 影片＋音效 | MiniMax H3 Ref2VA 剪枝 int8（本机 ComfyUI） | 有声影片＋对嘴＋首尾帧一次出；云端 Seedance 品质相近但每秒要钱 |
| 加速 | DMAD 4 步蒸馏 LoRA＋comfy kitchen INT8 注意力 | 8 类镜头并排看不出差、快约一半；EasyCache 会让近景糊 |
| 配音 | Breeze TTS 2 设计角色参考音（一次）→ **H3 拿参考音自己念台词**（`audio.voice_ref`）＋听写比对；BreezyVoice 固定音轨为备案 | 2026-10-23 起（原频道实测：像参考音的程度与 TTS 相近、同场一致性最高、表演较生动；本 repo 范本 2026-10-24 从头实测：RTX 5090、7 镜 6 句台词 H3 全部念对、成片自审五遍通过、整支 27 分钟）。之前 2026-10-07 起是 BreezyVoice 念所有台词（台湾腔比 Breeze／VoxCPM2 好、可标注音、Apache-2.0）；VoxCPM2 留作备用；Edge-TTS 只当声调对照「答案卷」 |
| 挑音 | faster-whisper ASR＋自制声调比对 | ASR 只验字，抓不到声调错 |
| 配乐 | MiniMax Music 3（纯器乐） | YuE2 会夹人声，且非商用 |
| 歌曲（有人声：MV、饶舌对决） | ① Suno（有帐号才用，例如经 Kie.ai）→ ② **本机 YuE2「14 版」范本**（没有 Suno 时先问使用者；`templates/song_yue2_v14/`、`tools/yue_song.py`＋`tools/pick_song.py`）→ ③ ACE-Step 1.5 XL（`tools/ace_song.py`）。饶舌对决整片：技能 `agent/skills/rap-battle/`＋范本 `pipeline/template_battle/` | 2026-10-27 中文饶舌对决实测：Suno 编曲最丰富、rap 最有攻击性；YuE2 melody 模式＋刷碟 rap 标签是本机最好，但约一半 seed 拍速跑掉，要多抽挑；ACE-Step 拍速最稳，但人声带金属声；MiniMax Music 3 唱词不照 BPM、前奏太长 |

| 空间 | Blender 方块人布置图 | 不锁空间，Image 2.5 会让学生背对黑板、窗户换边 |
| 协作 | Claude Code＋专案技能＋记忆 | — |

## 不做的事（以及原因）

- **不用 Avatar 平台**（HeyGen 等）：只能做主播式讲话，演不了戏。
- **不让 H3 写字**：中文会变乱码，标题、名片一律后制。
- **不做全身舞蹈远景**：768p 时脸只有几十像素，放大救不回。
- **不用遮罩擦过去做变身**：要用光流变形或 H3 首尾帧连续变化，观众要看到「变的过程」。
- **不从 Google Drive 挂载路径直接读取大模型**：Safetensors 依赖 mmap 随机寻址，FUSE 虚拟网络文件系统会导致加载卡死数十分钟或内核崩溃，且易触发 Google 24 小时配额封锁。详见 [colab_storage_architecture.md](file:///home/debian/lopy_project/lopy-workflow-colab/docs/colab_storage_architecture.md)。
