# 05 AI agent 协作与知识库

这个专案的脚本几乎都是 AI agent（Claude Code）写、也由它执行。真正让品质稳定的，是**让下一个 agent 知道上一个学到什么**。

## 入口档：CLAUDE.md

- 放在专案根目录，agent 每次开工自动读。
- **最新决策写在最上面**，每条一段：日期、做了什么、结论、连到详细文件。旧的不删，被取代就标「已被取代」。
- 固定段落：专案目标、影片规格、核心决策与否决理由、技术限制、工作注意事项（必读文件清单）。
- 范本：[agent/CLAUDE.md范本.md](../agent/CLAUDE.md范本.md)。其他 agent 用 `AGENTS.md`（Codex、opencode）、`GEMINI.md`，内容指向同一份知识。

## 知识库分层

| 层 | 放什么 | 例子 |
|---|---|---|
| 入口 | CLAUDE.md、专案现况 | 「现在做到哪、下一步」 |
| 总导航 | `资源索引/README.md` | 一行一个主题 |
| **答案索引** | 使用者已接受的做法：参数、踩坑、重现指令 | 「Image 2.5＋H3 制作与踩坑」「H3 快速模式与定稿验证」 |
| 实测 | 本机 A/B 结果、数字、并排影片 | 「DMAD 4 步 vs 14 步 8 类镜头」 |
| 研究 | 网路来源、社群做法（标明「已查阅未实测」） | 「16GB 跑 H3 社群报告」 |
| 每片纪录 | 剧本、制作纪录、PROGRESS | 每支片资料夹里 |

原则：
- 同一件事只有一个详细来源，其他地方只放连结。
- 「查阅过」≠「装了」≠「实测过」≠「使用者验收过」，四种状态分开写。
- 网路来源记原始网址、发布日、查阅日、验证状态。

## 记忆（一事一档）

Claude Code 的记忆资料夹，每个档案一件事，分四类：

| 类型 | 内容 | 例子 |
|---|---|---|
| feedback | 使用者给的规则与退件理由（附「为什么」与「怎么套用」） | 「老师不碰学生」「主角腰上以上」「交片前自己跑常退件清单」 |
| project | 专案事实与决定 | 「DMAD 4 步已定为定稿」「H3 单镜 ≤12 秒」 |
| reference | 外部资源位置 | 「角色声音参考档在哪」 |
| user | 使用者是谁、偏好 | — |

`MEMORY.md` 是索引，一行一条。**退件一次就写一条 feedback**，这是品质累积最快的方式。

## 技能（Skills）

- `agent/skills/shanshiba-drama/`：编剧九阶段流程＋阶段关卡、预设 9:16 剧本与镜表格式、生成前试映（16 宫格分镜草图＋读本）、审稿清单。
- `agent/skills/blender-previs/`：需求访谈 → 镜位契约 → 布置图检查 → 提示词包。

> ⚠️ 两个技能写于专案早期，里面还有「Seedance 2.5、30 秒一段」「Qwen 生图、768p」等旧说法。现行做法以 docs/ 为准（本机 H3、单镜 ≤12 秒、Image 2.5 首帧、DMAD）。

## 工作习惯（写进 CLAUDE.md 让 agent 遵守）

- 开工前先读现况和相关答案索引；收工前写回决策、成果路径、验证结果、限制、下一步。
- 多步骤工作开跑前**先报每一步的时间与费用**。
- 启动背景工作后**自己确认真的在跑**（log、伫列、GPU 使用率）。
- 「我去睡了」＝授权自动做完并自审，GPU 不要闲著；早上交成片＋自审报告。
- 一幕一幕做，做完先给人看；认可过的镜头不重拍。
- 使用者说「不要用 A 方法避开」时，不要擅自换别的绕路。
- 金钥不印出、不写进专案。

## 双机协作（选用）

原专案有两台电脑（5090 桌机、4080 笔电）共用云端硬碟资料夹，各跑各的 agent：
- 交接档各机一份、只改自己那份；CLAUDE.md 和 git 只在主机改。
- 笔电做不吃显存的工作：剧本、研究、剪接、ASR、QA、小型 LoRA 训练。
- 成品放 `交付_<机器>/<任务>/`，最后写 `done.txt`（档名、大小、SHA-256），对方看到 done.txt 且杂凑相符才使用。
