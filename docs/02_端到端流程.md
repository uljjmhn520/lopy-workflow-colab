## 1. 剧本

- 用编剧技能。先给 2–3 个叙事方向让人选，选定后写完整剧本＋镜表。
- 剧本就要考虑技术限制：避开快打、追逐；同一镜只让一个人说话；画面上要出现的字先想好由谁做（Image 2.5 画或后制叠）。
- 喜剧结构「神话层 × 真相层」：先拍得像史诗，切一镜揭穿其实很日常。

### 1.5 生成前试映（剧本定稿前的最后一关）

在花时间做首帧与 H3 之前，先让人「看」一遍（做法见 `agent/skills/shanshiba-drama/references/table-read.md`）：

1. 镜表写成 `preview/shots.json`（每镜：镜号、秒数、一句英文画面描述、台词文字 `text` 与字幕 `caption`）。
2. `python tools/make_storyboard.py preview/shots.json`：每 16 镜一张 4×4 铅笔草图（只看故事顺序与构图；要 `OPENAI_API_KEY`，没有就跳过，试映影片改成只有字幕）。
3. **2026-10-23 起读本只给文字、不做 TTS**（台词之后由 H3 拿角色参考音自己念，读本声音用不到成片）。`python tools/assemble_read.py preview/shots.json`：照镜表排时间轴 → 草图＋字幕的静音 `读本试映.mp4`、估计总长、最长三镜，以及每镜建议 H3 镜长 `h3_sec`＝max(3 秒, 台词字数 ÷ 3＋2 秒)（H3 有时晚 1.5–2.1 秒开口；原频道 7 句实测全部在这长度内念完，多的剪接时裁掉）。
4. 超长就删台词或并镜，不要加速；看完说「通过」才进首帧。
5. 之后的声音：每个角色录一份参考音（要吼的戏另录凶的）→ H3 自己念 → 听写比对 → 念错换 seed 抽 2 次 → 还错就请人录那一句当固定音轨、只重跑那一镜。要先「听」读本才做 TTS 读本（table-read.md 第 5 节）。原频道〈台风假作业包〉实测：读本 99.7 秒 → 删两镜、缩短无台词镜 → 88.6 秒。

## 2. Blender 预演（难的片才做）

- `make_plan.py` 写镜位契约（相机位置、目标、焦距、谁在哪）→ `render_layouts.py` 用无介面 Blender 算方块人布置图。
- 一张约 0.1 秒，13 张 1 秒左右。顺便发现「其实只有 8 个机位」这种重复。
- 布置图**左右镜射**后，和角色定妆照一起当 Image 2.5 的参考图，Image 2.5 照它的机位与站位构图（提示词写明「只照抄机位，不要方块外观」）。

## 3. 首帧

> **这份 repo 预设全本地**：角色与首帧改用 Qwen-Image 2.1／Qwen-Image-Edit，做法见 [07_本地角色与首帧.md](07_本地角色与首帧.md)，完整范例是 `pipeline/demo_local/run_demo.py`。下面是原专案用云端 Image 2.5 时的写法，构图、光线、参考图的原则一样适用。


`gen_frames.py` 的 SHOTS 表每一列：`(参考图代号, 光线, 画面描述, 选项)`。

- 先生「场景母版」（例如阿禾的房间），之后每镜都拿母版当参考，房间才会一致。
- 每镜参考图＝角色定妆照＋场景母版＋布置图（有的话）。
- 提示词模板固定：保持角色外观句、电影感句（变形镜头、35mm 颗粒、浅景深、青橘调、**不要黑边**）、不准有字句、制服句。
- `n=1`、`quality=medium`；参考图自动缩成一半面积省钱。
- **人工审首帧**后建立空档 `frames_ok`，后面的 H3 才会开跑。
- **草稿模式（选用）**：`tools/gen_image.py --turbo`（Qwen-Image 2.1 Turbo，固定 8 步、官方 sigma；`setup/downloads_qwen_turbo.json`）一张 2K 约 12 秒（原版 50 步约 63 秒），拿来一次抽很多构图挑。皮肤偏光滑、特定表情会偏向微笑、暗部偏黑 → **定稿仍用原版 50 步**。`qwen21_face_refine.py --turbo` 同理（实验性）。
- 动作镜的首帧画「动作开始前」的姿势（见下方 6.「动作写法」）。

## 4–5. 配音与挑音

```
（2026-10-07 起：台词表 → jobs.json → make_breezyvoice.cmd，念不准的字标注音；下面是〈D-7〉范例当时的旧流程，留作参考）
voice_plan.py   台词表 LINES＋TTS 用字替换（念不准的字换同音字，字幕不变）
      ↓
voice_stage1.py ① 参考音逐字稿（ASR）② 产生 Breeze 任务 ③ edge-tts 台湾国语「答案卷」④ VoxCPM2 每句 6 候选（繁转简送入）
      ↓
breeze_batch.py Breeze 每句 6 候选
      ↓
voice_pick.py   去头尾静音 → 太慢的淘汰 → ASR 必须全对 → 每字音高曲线跟答案卷比
                → 一声不够高、升降方向相反额外扣分 → 取最低分
```

- 候选越多越好，一批常常只有 1 个全过。
- 背景很吵的镜头，先把环境音叠上去再跑 ASR（`voice_robust.py`），挑在噪音下仍听得清楚的。
- 换了配音，有台词的 H3 镜头要重拍（嘴型跟著音轨走）。
- **口播／旁白稿**（解说片、开场旁白）：`tools/make_narration.py lines.json out --ref 参考音.wav --ref-text "逐字稿"`。BreezyVoice 一次念 2–3 句（同一段内并块），块与块之间的停顿照结尾标点；自动听写挑候选、切掉句尾多念的小字，输出 `narration.wav`＋`timeline.json`（每句起讫秒数，给字幕用）。不合格的块 `--reroll K04,K11` 重抽。比一句一句接、固定停顿顺很多。

## 6. H3 生成

> **云端替代（选用）：Seedance 2.5（Kie.ai）**。使用者明说才用。`tools/sd25_shot.py` 吃跟 H3 **同一份分镜 spec**，可以拿来和 H3 版比较：
> ```
> python tools/sd25_shot.py check  h3/*/spec.json                 # 每镜模式、秒数、总点数（不送件、不用金钥）
> python tools/sd25_shot.py submit h3/*/spec.json --out sd25      # 送件（KIE_API_KEY；先查点数，不够就不送）
> python tools/sd25_shot.py poll   --out sd25                     # 做好下载成 sd25/<镜>.mp4
> ```
> - **有台词的镜一定给角色参考音**：spec 有 `audio.voice_ref` → 参考模式（首帧当参考图＋参考音，只学音色）；有台词没参考音会被挡下，只有角色真的没有参考音才在 spec 写 `"self_voice": true`。没台词的镜走首帧模式（构图钉在首帧）。
> - 720p、每镜 ≥4 秒、约 63 点／秒。原频道〈台风假作业包〉26 镜比较：2.5 动作与表情较生动（真的跳起来、仰头），但跳跃时脸会糊、偶尔整个换构图；H3 脸与服装最稳、动作偏小（下面「动作写法」可以补回大半）。
> - **换声（选用）**：2.5 自己重念的台词，可用 `tools/cosy_vc.py` 换成角色参考音的音色，每个字的时间不变、嘴型照对（BreezyVoice venv；先用 BS-RoFormer 分离出人声再换、再混回）。作者实测 14 句：像角色参考音 0.16 → 0.69。念错的声调会跟著保留，那句改用 TTS 重配。
> - **换字（选用，2026-11-07）**：只错一两个字时不用整句重配，`tools/vc_swap.py job.json`：MMS 强制对齐找到那个字 → Ming 用角色参考音念含那个字的小句 → 切下那个字、照前后字音高移调、拉成原长度接回 → 整句 cosy_vc 换声抹平接缝。整句长度不变、嘴型照对；同音字技巧可用（`tts`／`tts_at`／`tts_char`）。适合声调错、破音字；嘴型差很多的字要看画面。格式见档头，接缝一定要人听。

### 动作写法（2026-10-23 起预设，H3 动作偏小的主要解法）

H3 照字面演：spec 的 `action` 只写一句「全班跳起来欢呼」，它就只会举手晃一晃。照 MiniMax 官方提示词技能 `h3-prompt-writing` 的结构写，动作才会出来：

- **`action` 写 50–120 个英文字**：「Starting from <Picture 1>, …」**首帧定锚 → 动作开始 → 持续发展 → 结果**；写出哪个身体部位动、动多大（"until the arms are fully straight"）、做几次（"again and again"、"about three swipes per second"）；不写 lively、exaggerated 这类抽象词（模型不知道要夸张到哪）。
  - 例：「全班跳起来」→ "…bend their knees deeply and spring straight up so their feet leave the floor, then land and jump a second time, pumping both fists above their heads with each jump…"
  - 镜内时间点（"at about 1.2 seconds …"）选用：官方没有这条，作者实测只多一点点，要对节拍时再写。
  - 大动作镜、背景容易冒人的镜，action 前先加 2–4 句首帧描述（构图、人物外观与位置、光线）：动作量不变，但画面较钉在首帧（作者 2026-10-24 补测：跳跃头不出框、背景不冒人）；一般镜不必写到官方建议的 350–500 字。
- 作者实测（6 个动作镜 × 2 seed，光流量动作）：一句话版 0.41 → 官方结构 1.10（**×2.7**）→ 再加时间点 1.19；狂刷手机从完全静止变成拉近手机＋踢脚、偷偷握拳变成左右张望＋拳头拉到腰。`tools/h3_shot.py` 对少于 50 字的 `action` 出警告。
- **动作镜首帧画「动作开始前」的姿势**：首帧已经举手、握拳（动作最高点），H3 只剩维持可演。弹跳等全身大动作首帧要留头顶空间（跳太高头会出框、中段糊）。
- **尾帧＝首帧会把人锁回原姿势**（实测三种写法都 100% 静止）：只用在人不需要动、只要锁道具／萤幕字的镜；人要动时尾帧另做「动作完成后的姿势」，或不锁、多抽 seed。`h3_shot.py` 侦测到尾帧＝首帧会提醒。
- 动作变大时台词较容易漏字、晚开口 → 有台词的动作镜逐镜听写、抽 2 seed。
- 让 agent 照官方规则写：装官方技能（只是写作规则，没有程式）：`npx skills add https://github.com/MiniMax-AI/MiniMax-H3 --skill h3-prompt-writing`，或把官方 repo 的 `skills/h3-prompt-writing/` 复制到你的 `.claude/skills/`。组提示词仍交给 `h3_shot.py`（它照官方 Ref2VA 六段格式），技能只用来写 `action`。

### 舞蹈、武打：白模动作参考（2026-10-14 起）

照原片动作做的镜头（舞步、武打）不用骨架控制，改成「原片 → 灰色 3D 白模影片 → 当 H3 的动作参考」，手臂形状、踢脚、落地时间都比骨架准：

```
C:\AI\H3\venv\Scripts\python.exe tools\make_whitemodel.py 原片.mp4 --out 白模.mp4 --start 13.72 --frames 124 --crop 1600:880:220:155 --size 1280x704
```

- 需要 ComfyUI ≥ 0.37（SAM 3D Body、MoGe、SAM 3.1 都是内建节点）＋`setup/downloads_whitemodel.json` 的 4 个模型（约 7.2 GB）。124 格单人约 25 秒、双人约 55 秒。
- `--crop`／`--size` 先把原片裁到跟首帧人物同位置、同大小；`--frames` 用 17n+5。
- **两人以上加 `--people 2 --colors red,blue`**（每人固定颜色，身份较不会对调；需要把 `setup/comfy_nodes/whitemodel_color` 复制到 `ComfyUI/custom_nodes/`，重启 ComfyUI）。工具会印出第 0 格哪个颜色在左／右。
- spec 写 `"camera_video": {"file": "白模.mp4", "kind": "motion"}`（多人加 `"people": 2`、`"colors": ["red", "blue"]`，依 subjects 顺序），`h3_shot.py` 会自动写成「<Video 1> 只是动作参考」。
- 白模没有道具（刀、球），道具写进 `action`；原片只取动作，成片不能出现原片画面，原片要是你有权使用的素材。
- 其他 spec 选项：`"control"` 可给清单叠多组控制（预设 Fun ControlNet Union 2.0，合计强度 ≤1）；`"first_clip"`＝上一段最后 5／22／39 格当开头接续长动作；`"raw_prompt"` 跳过六段格式（给只认单一 caption 的 LoRA）。

`plan_h3.py` 的 SHOTS：每镜角色、动作（英文）、台词与开口秒数、长度、首帧、尾帧、限制句、环境音。

`pipeline_gen.py` 做的事：
1. 读 `voice_state.json` 算每镜时间轴（台词起点＋长度，至少留 0.6 秒尾巴）。
2. 产生固定音轨 `specs/<id>_guide.wav`：台词放在指定秒数，其他全是静音。**不说话的镜头也给静音**，角色才不会乱开口。
   例外：没有人的镜头（萤光笔、印表机）设 `native=True`，让 H3 自己出音效。
3. 写 `specs/<id>.json` 交给 `h3_shot.py`：组官方六段提示词 → 格式检查 → 送 ComfyUI。
4. 即时品检：自己切镜、黑画面、首尾漂移；不合格换 seed，最多 3 次。

**现行预设：spec 加 `"draft": true` ＝ DMAD 4 步。** 〈D-7〉当时还是 14 步，之后的片都改 DMAD。以下镜头仍用 14 步：骨架控制的舞蹈、群舞、细腻的含泪表情、Combat LoRA 拉满的打斗。

`run_queue.sh`：每 60 秒看 GPU，使用率 <20% 且 ComfyUI 伫列空连续 3 次才开工，先叫 ComfyUI 释放显存，确认显存真的空了再跑。依序：配音 → Breeze → 挑音 → 等 `frames_ok` → H3。

## 7. 放大

- **放大前：远景小脸精修（选用，2026-10-24 加入）**。远景／舞台／教室前方的重要角色，成片（768×1344）脸平均高 < 50 px 时，用 `tools/face_refine.py`：逐格追脸 → 裁大 → H3 低强度重画（照角色定妆照认人、原片音轨锁住对嘴）→ 只把脸羽化贴回，每镜约 30 秒（RTX 5090）。原频道 3 镜实测：脸 25–30 px 从一团糊变成认得出本人，还修掉 H3 画错的眼镜；70 px 几乎没差（工具自动跳过 ≥ 50 px）；不闪；嘴大致跟原音（有台词仍要人看）。
  ```
  C:\AI\H3\venv\Scripts\python.exe C:\AI\tools\face_refine.py <镜资料夹> --ref <角色定妆照> --track          # 6–9 秒：脸多大、选到谁（preview.png）
  C:\AI\H3\venv\Scripts\python.exe C:\AI\tools\face_refine.py <镜资料夹> --ref <角色定妆照> [--select top_most]
  ```
  吃 `h3_shot.py` 的输出资料夹（`clip.mp4`＋`shot.json`，提示词自动组），输出 `<镜资料夹>/facerefine/refined.mp4`。**先 `--track` 看选到的是不是主角**：前景有更大的路人脸时改 `--select top_most`／`left_most`…；一次修一张脸。顺序：H3 → face_refine → VSR。安装与限制（只在 ComfyUI 0.40 实测）见 `docs/06_安装.md`。
- `assemble.py --vsr`：16:9 的 H3 片段先用 RTX VSR ULTRA 放到 1080p（每镜约 10 秒），快取在 `post/vsr/`。重拍后自动作废旧快取。
- 全景、舞蹈改用 FlashVSR（要逐镜看有没有多画细节）。
- 不用 SeedVR2、SoL-Refiner：会改脸、改嘴型。

## 8. 后制素材（`post_fx.py`）

全部用 PIL＋numpy 逐格画，不用剪辑软体：
- 撕日历字卡（倒数 D-7、D-1、D-0）
- 咒印名片：法阵慢转＋标楷体逐字由光浮现＋爆光（`templates/seals/`）
- 手机聊天画面、角落时间字、三分割栏位的灰／亮调色

## 9. 配乐（`music_scenes.py`）

1. 依 `post/starts.json` 算每段需要几秒。
2. 每段 MiniMax Music 3 生 3 个 seed；歌词栏只放 `[Instrumental]` 标签（约 14 个，太少会太短）。
3. BS-RoFormer 分离，选人声残留最低的那个（避免像人声的长音盖过台词）。
4. 不够长就交叉淡化循环，段与段 2 秒交叉淡化，逐秒调音量。

## 10. 组装（`assemble.py`）

SEGS 表决定整支片的顺序，每段一种类型：`h3`（片段＋裁切）、`split`（三分割）、`cal`（字卡）、`card`（全画面名片）、`phone`、`end`（片尾）。

- **`trim`／`ss` 裁掉 H3 开口前的空白**（H3 常晚 1.4–2.8 秒才开口）。
- **修剪点一律对齐 1/24 秒**（2026-10-23 修正，范本 `make_film.py` 已改）：每段用 `-frames:v` 取整数格，修剪点没对齐的话每镜多出零点几格，25 镜累积约 0.3 秒，中段以后嘴型明显晚于声音。自己写组装脚本时，把每镜的起讫秒数先四舍五入到格，再用同一个格数排声音。
- 配音比画面提前 0.2 秒（`SAY_LEAD`）对嘴最自然。
- 音讯：环境音底（可直接借 H3 原生环境音延长）＋音效库（`sfx/`）＋配乐；台词时背景压到 30%。
- 响度两段式：loudnorm → 量测后补到 −15.5 LUFS → 限幅。确切指令（`example_D-7/assemble.py` 第 359–363 行）：
  ```
  ffmpeg -i mix.wav -af loudnorm=I=-15.5:TP=-1.5:LRA=11 -ar 48000 ln.wav
  ffmpeg -i ln.wav -af ebur128 -f null -          ← 读最后的 I: 数值，gain = -15.5 - I
  ffmpeg -i ln.wav -af "volume=<gain>dB,alimiter=limit=0.72:level=false" -ar 48000 final.wav
  ```
  **`alimiter` 一定要加 `level=false`**：预设 `level=true` 会把输出自动拉到 0 dBFS（2026-10-07 全新安装测试踩到：成片峰值 0.0 dBFS、−14.6 LUFS）。目标：约 −15.5 LUFS、峰值 −2 dBFS 以下。
- 字幕依说话者上色、句号拆段、前后不重叠。
- 同时输出手机版 720p（给人在手机上验收）。
